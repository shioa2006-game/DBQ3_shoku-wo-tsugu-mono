## 何を基準にするか

1. **実装済みの動作・台詞は現在のコードを基準にする。** 資料が異なれば資料を直す。コード内のコメントにも旧仕様が残り得るので、実際の処理・データを確認する。
2. コード同士の不整合は、片方を勝手に正史として消さず、双方の出典と影響を[一覧](inconsistencies.md)へ記録する。ゲームの変更は別作業で判断する。
3. 第6～7章の仕様は `planned/` に置く。ステージ名・演出・完了条件が書かれていても実装済みと扱わない。第1～5章の事実と相違があれば、実装基準の資料を優先する。
4. 過去資料は `archive/story/2026-11-03/` に原文保存する。旧配置には移転案内だけを残し、並行して仕様を書き足さない。過去の「確定」「Done」「正本」は現行仕様を保証しない。

## 更新のしかた

ストーリー変更時は、対象章の実装とその章資料を一緒に確認してください。人物・書・章間の受け渡しが変わる場合は全体像と人物表も更新します。解決した不整合は削除せず、解決内容と根拠を追記します。

台詞全文の正本は `src/content/` および第1章の `src/game/quests.js`・`src/ui/ui.js` です。資料側では出来事、成立条件、人物の役割を説明し、台詞全文を別管理しません。日常会話は各ゲームの `src/content/smalltalk.js` も確認してください。

運用・テストの手順は[親のAGENTS.md](../../AGENTS.md)と各ゲームのAGENTS.mdに従います。ここはゲーム起動・セーブ領域を統合するための仕様ではありません。
