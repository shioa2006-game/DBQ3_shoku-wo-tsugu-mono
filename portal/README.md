# 共通トップページ

ルートの [index.html](../index.html) が、プレイヤー向けの共通入口です。

- 第1～3章「ジパング復興編」、第4～5章「火山島編」、第6～7章「ダーマ再興編」の各タイトル画面へ移動します（第6～7章は2026-11-14に追加）。
- PCでは3カラム、小さい画面では縦並び。ゲーム自体はキーボード・マウス操作です。
- Studioや開発用ページへのリンクはありません。
- ページはHTML/CSSと静止画像だけで動作し、ゲームのセーブを読み書きしません。外部フォントやCDNへの依存もありません。
- 書体・黄色のタイトル・青いボタンはCH1～3のタイトル画面に合わせています。編名26px、紹介文16px、ボタン17pxとし、各編の案内は画像・章番号・編名・紹介1文・ボタンに絞っています。

## 確認用の出力を作る

親リポジトリで実行します。各ゲームの依存関係はルートREADMEの手順で準備してください。

```powershell
node tools/build-portal.mjs
# 最後に表示されたフォルダ名を指定する
node tools/serve-portal.mjs work/portal-build-XXXXXX
```

確認URLは `http://127.0.0.1:5188/DBQ3_shoku-wo-tsugu-mono/` です。ポートが使用中の場合は、既存サーバーを停止せず `node tools/serve-portal.mjs work/portal-build-XXXXXX 5189` のように明示指定します。

ビルドは毎回新しい `work/portal-build-XXXXXX/` を作り、3つのゲームを順番にその中へ出力します。`RELATIVE_ASSET_PATHS=1` を子プロセスだけに設定し、既存のゲームの `dist/`・開発サーバー・テスト用ポート4174を変更しません。出力には現在の作業ツリーのゲーム内容が含まれるため、並行作業の未コミット変更もローカル確認結果には反映されます。

ルートを単純な静的サーバーで配信するだけでは、各ゲームのソースは起動できません。必ず上記のビルド出力でリンク先を確認してください。

## 公開時の配置

```text
index.html
portal/styles.css
portal/images/...
dqb3-tsugumono-ch1-3/index.html + assets/...
dqb3-tsugumono-ch4-5/index.html + assets/...
dqb3-tsugumono-ch6-7/index.html + assets/...
.nojekyll
```

リンク・CSS・画像・ゲームの生成アセットは相対パスです。GitHub Pagesのプロジェクト配下でも配置を維持できます。確認サーバーも同じプロジェクトパス配下で配信します。

公開処理は [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) です。GitHubのSettings → Pages → Sourceは **GitHub Actions** を選びます。`main` の共通トップ・3つのゲーム・`game-shared/`・公開処理に関する変更をpushすると、依存関係をlockfileからインストールし、このビルド出力だけを公開します。公開前に、各編の `tests/e2e/blueprint.test.mjs` を公開用の相対URLで順番に実行します。Studio・開発用ページ・ソース一式は公開成果物に含めません。

公開先は https://shioa2006-game.github.io/DBQ3_shoku-wo-tsugu-mono/ です。Actionsの「共通トップと3つのゲームを公開」から手動実行もできます。ビルド失敗時は公開ジョブが動かず、直前の公開内容が維持されます。公開後は各編のタイトル画面と、画面内のビルドIDを確認してください。

各編の起動・セーブキー・既存タイトル画面は独立したままです。3つの編は同じオリジン（同じ保存領域）に並びますが、それぞれ自分のキーだけを読み書きします。実際の公開先のオリジンを変更する場合、ブラウザー内の既存セーブが別の保存領域になる点を公開時に確認してください。

## スクショへの差し替え

第1～3章はユーザー提供のゲームスクリーンショット `images/zipangu-gameplay.png` を使用しています。原画像（1916×940）を保持し、CSSで左上(384, 110)から1152×704の範囲を切り抜いて表示します。主人公と森・岩山を残し、HUDを表示範囲から外しています。元画像を変更する際は `.chapter-art--zipangu` の切り抜き位置も調整してください。

第4～5章もユーザー提供のスクリーンショット `images/volcano-gameplay.png` を使用します。原画像（1913×944）を保持し、`.chapter-art--volcano` のCSSで左上(382, 110)から1152×704を表示します。第1～3章と同じ18:11の枠に主人公と火山を収め、HUDを枠外にしています。実際のゲーム画面への差し替えに伴い「イメージ」の表示を削除しました。

第6～7章は、ゲームの画面から作った `images/dharma-gameplay.png`（1152×704）を使用します。第6章を終えた状態で、主人公を道の口の南（x32・z62）に積んだ神殿の石の足場（高さ y31）へ立たせ、画面の表示（ハート・目的・時計・ホットバー）を隠して、幅1916×高さ940の画面の左上(384, 110)から1152×704を切り出しました。既存2編と同じ切り抜き位置なので、主人公の位置と大きさがそろいます。切り抜き済みの画像なので、専用のCSSはありません。仮のSVGイラスト（`images/dharma.svg`）と「構想イメージ」の表示は使わなくなりました（ファイルは残しています）。ユーザーが撮ったスクリーンショットへ差し替える場合は、次の手順に従います。

1. 撮影した画像を `portal/images/` に置きます。推奨比率は18:11（例: 1440×880）です。
2. `index.html` の対応する `img` の `src` と `alt` を更新します。寸法も画像の比率に合わせます。
3. 正式なゲームスクショへ置き換えたカードでは「イメージ」のラベルを削除できます。
4. 被写体の位置は必要に応じてCSSの `object-position` で調整し、デスクトップと縦並びの両方で確認します。

新しい編を足すときは、完成したゲームを `tools/build-portal.mjs` の `games` と公開処理（依存関係の準備・変更を見るパス・設計図テスト）へ加え、カードのボタンを実際の相対リンクにします。公開前に架空のリンクを有効にしないでください。
