# 共通トップページ

ルートの [index.html](../index.html) が、プレイヤー向けの共通入口です。

- 第1～3章「ジパング復興編」、第4～5章「火山島編」の既存タイトル画面へ移動します。
- 第6～7章「ダーマ再興編」は準備中。リンクを持たない無効ボタンです。
- PCでは3カラム、小さい画面では縦並び。ゲーム自体はキーボード・マウス操作です。
- Studioや開発用ページへのリンクはありません。
- ページはHTML/CSSと静止SVGだけで動作し、ゲームのセーブを読み書きしません。外部フォントやCDNへの依存もありません。
- 書体・黄色のタイトル・青いボタンはCH1～3のタイトル画面に合わせています。編名26px、紹介文16px、ボタン17pxとし、各編の案内は画像・章番号・編名・紹介1文・ボタンに絞っています。

## 確認用の出力を作る

親リポジトリで実行します。各ゲームの依存関係はルートREADMEの手順で準備してください。

```powershell
node tools/build-portal.mjs
# 最後に表示されたフォルダ名を指定する
node tools/serve-portal.mjs work/portal-build-XXXXXX
```

確認URLは `http://127.0.0.1:5188/DBQ3_shoku-wo-tsugu-mono/` です。ポートが使用中の場合は、既存サーバーを停止せず `node tools/serve-portal.mjs work/portal-build-XXXXXX 5189` のように明示指定します。

ビルドは毎回新しい `work/portal-build-XXXXXX/` を作り、2ゲームを順番にその中へ出力します。`RELATIVE_ASSET_PATHS=1` を子プロセスだけに設定し、既存のゲームの `dist/`・開発サーバー・テスト用ポート4174を変更しません。出力には現在の作業ツリーのゲーム内容が含まれるため、並行作業の未コミット変更もローカル確認結果には反映されます。

ルートを単純な静的サーバーで配信するだけでは、各ゲームのソースは起動できません。必ず上記のビルド出力でリンク先を確認してください。

## 公開時の配置

```text
index.html
portal/styles.css
portal/images/...
dqb3-tsugumono-ch1-3/index.html + assets/...
dqb3-tsugumono-ch4-5/index.html + assets/...
.nojekyll
```

リンク・CSS・画像・ゲームの生成アセットは相対パスです。GitHub Pagesのプロジェクト配下でも配置を維持できます。確認サーバーも同じプロジェクトパス配下で配信します。

**公開設定は未変更です。** GitHub Pagesへは、このビルド出力をサイトのルートとして配信する設定が別途必要です。ソースのルートだけを公開してもゲームは動きません。今回GitHub Actionsの追加・公開先変更・デプロイは行っていません。

各編の起動・セーブキー・既存タイトル画面は独立したままです。実際の公開先のオリジンを変更する場合、ブラウザー内の既存セーブが別の保存領域になる点を公開時に確認してください。

## スクショへの差し替え

現在の3枚はこのページ用に作成した仮のSVGイラストです。実際のゲーム画面と誤認しないよう「イメージ」と表示しています。

1. 撮影した画像を `portal/images/` に置きます。推奨比率は18:11（例: 1440×880）です。
2. `index.html` の対応する `img` の `src` と `alt` を更新します。寸法も画像の比率に合わせます。
3. 正式なゲームスクショへ置き換えたカードでは「イメージ」のラベルを削除できます。第6～7章の構想画像は区別を残してください。
4. 被写体の位置は必要に応じてCSSの `object-position` で調整し、デスクトップと縦並びの両方で確認します。

第6～7章公開時は、完成したゲームの出力を追加し、準備中ボタンを実際の相対リンクへ変更します。公開前に架空のリンクを有効にしないでください。
