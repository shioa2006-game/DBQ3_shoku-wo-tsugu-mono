## 1. 目的と現在の確認結果

第1〜3章のプレイ動画解析とプレイ確認で確定した次の2点を、第4〜5章にも反映する。

1. **無限の石バグ**: 世界の底より下（範囲外）を照準で叩くと、掘っても消えない
   仮想の石からドロップが湧き続ける。
2. **穴の中のカメラ**: 掘った穴などでカメラが地形に埋まり、地中の裏面や
   世界外の虚空が見えて操作対象を見失う。

第4〜5章側を確認したところ、次の状態だった。

- `src/world/world.js` の `get()` は範囲外（特に `y < 0`）で物理用に `B.STONE` を
  返す一方、`set()` は範囲外に書き込めない。**`raycast()` に範囲外ガードが無く、
  第1〜3章と同じ無限の石バグが存在する**（修正前の共通コード）。
- `src/main.js` の `updateCamera()` に遮蔽物の自動ズーム（`camZoom`）は
  実装済みだが、**ズームの下限（0.22）が原因で、1〜2ブロックの穴では
  カメラが壁の中に残る**（第1〜3章と同じ修正前のコード）。

第4章は坑道の採掘・火山の崖が舞台の中心で、深い穴や狭い通路でカメラが
埋まる場面は本島編より**多い**。底掘りも鉱夫プレイで起きやすく、
両修正の移植価値は高い。

## 2. 修正A: 無限の石バグ（範囲外レイキャストの遮断）

### 2.1 問題の構造

1. プレイヤーが世界の底（y0）のブロックを掘り抜く。
2. 底の穴ごしに `y = -1` のセルへ照準を合わせる。
3. `world.get(x, -1, z)` は範囲外だが物理用に `B.STONE` を返すため、
   `raycast()` がこの**仮想の石**をヒットとして返す。
4. 採掘処理が成立してドロップ（石）が湧くが、`world.set()` は範囲外に
   書き込めないため、セルは永遠に「石」のまま。→ 掘るたび石が増える。

### 2.2 実装

`src/world/world.js` の `raycast()` のヒット判定を範囲内に限定する（第1〜3章と同一）。

```js
    for (let i = 0; i < 256; i += 1) {
      // 範囲外セルは照準に当てない。世界の外（特に底より下）は get() が
      // 物理用に「石」を返すが set() では消せないため、ここが照準に当たると
      // 「掘っても消えず、ドロップだけ湧き続ける無限の石」になってしまう。
      if (this.inBounds(x, y, z)) {
        const id = this.get(x, y, z);
        if (id !== B.AIR && id !== B.WATER) {
          return { x, y, z, id, nx, ny, nz, dist };
        }
      }
      ...（DDAのステップ処理は従来どおり）
```

あわせて `src/main.js` の `breakBlock()` 先頭に最終保険を入れる。

```js
  breakBlock(x, y, z, bdef) {
    if (!this.world.inBounds(x, y, z)) return; // 世界外の仮想ブロックは壊せない（最終保険）
```

### 2.3 影響範囲の確認

- エンティティの衝突・水泳などの物理は `get()`/`isSolid()` を直接使っており、
  `raycast()` の変更の影響を受けない（範囲外が「石」扱いのままでよい）。
- カメラの自動ズームも `raycast()` を使うが、範囲内の遮蔽物判定は不変。
- 設計図クリック（`pickGhostCell`）・設置は既に範囲内チェックがあり不変。

## 3. 修正B: 穴の中のカメラ寄せ（ズーム下限の撤廃）

### 3.1 問題の構造

自動ズームは「遮蔽物の0.7手前まで寄る。ただし軌道半径の22%まで」という式で、

```js
    const wantZoom = hit ? Math.max(0.22, (hit.dist - 0.7) / viewLen) : 1;
```

遮蔽物が近い（1〜2ブロックの穴の中など）と `hit.dist - 0.7` が下限の0.22を
下回り、**カメラが遮蔽物（壁）より遠くへ置かれて壁の中に残る**。この状態で
地中の裏面や世界外の虚空が見え、操作対象を見失う。

### 3.2 実装

下限を「壁の8割地点まで寄る」に置き換える（第1〜3章と同一）。
カメラが壁の内側（穴の中）へ降りてきて、キャラクターが大写しで見え続ける。

```js
    // Occlusion auto-zoom: if terrain (e.g. tree canopy) blocks the view line,
    // pull the camera in front of the blocker; ease back out when clear.
    // 遮蔽物が近い（掘った穴の中など）ときは壁の8割地点まで寄り、カメラを
    // 壁の中に残さない。穴の中でもキャラクターが大写しで見え続け、黒幕や
    // 地中の虚空を見せずに済む（最低距離0.45で頭の中までは寄らない）。
    const wantZoom = hit
      ? Math.min(1, Math.max(hit.dist - 0.7, hit.dist * 0.8, 0.45) / viewLen)
      : 1;
```

- `hit.dist - 0.7`: 遮蔽物が遠い通常ケース（木の葉など）は従来どおり0.7手前。
- `hit.dist * 0.8`: 遮蔽物が近いときは壁の2割手前まで寄る（壁の中に残らない）。
- `0.45`: プレイヤーの頭の中まで寄らない最低距離。

### 3.3 第4〜5章固有の注意

- 坑道（第4章の鉱山）は天井のある狭い通路が多く、寄せ込みの発動機会が
  本島編より多い。**狭い坑道でカメラが激しく前後しないか**（snap-in 14 /
  ease-out 2.2 の既存レートのままで自然か）をユーザー確認の重点にする。
- 溶岩・黒竹・火山岩など火山島特有のブロックも `raycast()` の遮蔽対象で
  あることは従来と同じ。挙動変更は「近距離での寄せ方」だけ。
