## 1. 目的と第4〜5章側の現状

第1〜3章で修正済みの次の2点を、第4〜5章にも反映する。

1. HP満タン・半減・空のハートを同じ字形と固定サイズで描画し、状態が変化しても大きさと間隔がずれないようにする。
2. 水中にいる人間型・非人間型について、画像と3D部品へ同じ水中表現を適用し、全体の視認性も改善する。

第4〜5章側を確認したところ、どちらも第1〜3章の修正前と同じ状態である。

- `src/ui/ui.js` は白い文字ハート `❤` と黒い絵文字ハート `🖤` を混在させている。
- `src/style.css` はハートごとの固定幅・固定高を持たず、字形の違いがそのまま大きさと間隔のずれになる。
- 水面は `opacity: 0.82`、`renderOrder: 2` で描画される。
- 人間型の頭と胴体の画像だけが `renderOrder: 14` / `12` で水面より後に描画される。
- 主人公だけが水深に応じた色補正を持ち、住民とモンスターには同じ処理がない。
- 通常モンスターは毎フレーム基本色または被弾色へ戻され、水中色を保持する仕組みがない。

この結果、ハートではWindows上の絵文字フォント差による位置ずれが起き、水中では頭・胴体画像だけが鮮明で、3Dの手足・装備・モンスター画像が強く水面に覆われる不統一が起き得る。

## 2. 修正A: HUDのハート表示を統一する

### 2.1 原因

現在の `src/ui/ui.js` はHP状態によって別の文字を使っている。

```js
html += `<span class="heart ${cls}">${v >= 2 ? "❤" : "🖤"}</span>`;
```

`❤` は文字として描画される一方、`🖤` はカラー絵文字として描画される環境がある。両者はフォント、外接寸法、送り幅が異なるため、空のハートだけ大きくなり、後続のハート位置もずれる。

### 2.2 決定仕様

1. 満タン・半減・空の全状態で同一の文字ハート `❤︎` を使う。
2. 状態の違いは文字ではなくCSSの色で表す。
3. 各ハートを `24px × 24px` の固定領域へ中央配置する。
4. ハート列はFlexboxと `gap: 3px` で等間隔に並べる。
5. 最大HP、ハート1個あたりのHP量、半減判定は変更しない。

### 2.3 実装

`src/ui/ui.js` の `setHp()` では、すべての状態に同じテキスト表示用字形を使う。

```js
html += `<span class="heart ${cls}">&#10084;&#65038;</span>`;
```

`src/style.css` は次の方針へ変更する。

```css
.hearts {
  position: absolute;
  top: 14px;
  left: 16px;
  display: flex;
  align-items: center;
  gap: 3px;
}

.heart {
  display: inline-grid;
  place-items: center;
  width: 24px;
  height: 24px;
  box-sizing: border-box;
  color: #f7fbff;
  font-family: "Segoe UI Symbol", Arial, sans-serif;
  font-size: 24px;
  line-height: 1;
  text-shadow: 0 2px 3px rgba(0, 0, 0, 0.6);
}

.heart.half  { color: #a9bdd7; }
.heart.empty { color: #282536; }
```

第1〜3章の2ファイルは第4〜5章と同じ構造なので、この修正はほぼそのまま移植できる。

### 2.4 確認項目

- 最大HP時、1個以上減った状態、半端なHP、HP 0の各状態で全ハートの幅と高さが一致する。
- HPが変化してもハート列全体の先頭位置と各ハート間の間隔が動かない。
- Chrome / Edge上で黒いカラー絵文字へ戻っていない。
- 可能ならPlaywrightで各 `.heart` の `getBoundingClientRect()` がすべて `24 × 24` であることと、全要素の `textContent` が同じであることを確認する。

## 3. 修正B: 水中の描画テイストと視認性を統一する

### 3.1 原因

水中表現に次の3種類の処理が混在している。

1. 水面メッシュによる青い半透明の覆い
2. 主人公のリグだけに適用される水深連動の青色・減光処理
3. 主人公の頭・胴体画像だけを水面より後へ強制描画する高い `renderOrder`

特に3番目により、画像の頭・胴体は水面の影響を受けず、同じキャラクターの3D手足・装備は水面に覆われる。住民は個体単位の水中色を更新せず、通常モンスター画像も水中色を持たないため、種別によって見え方が異なる。

### 3.2 決定仕様

1. 人間型の頭・胴体画像、3Dの手足、装備へ同じ水深連動色を適用する。
2. 住民にも主人公と同じ水深計算を適用する。
3. 通常モンスター画像にも同じ水深計算と色補正を適用する。
4. 人間型画像とモンスター画像を水面より前に強制描画せず、水面の半透明表現を全体へ共通して掛ける。
5. 水中の青色補正と減光を弱め、水面の不透明度も下げて、統一感を保ちながら手足・装備・モンスターを判別できる明るさにする。
6. 被弾時の赤色、モンスター固有の色替え、死亡状態など既存の基本色を先に決め、その色へ水中補正を重ねる。
7. 名前、会話マーカー、HPバー、HUDなどのUIは読みやすさを優先し、水中の色補正対象に含めない。
8. セーブ形式とワールド生成バージョンは変更しない。

### 3.3 共通処理

`src/entities/rig.js` に水深計算と色補正を共通関数として置く。

```js
const UNDERWATER_COLOR = new THREE.Color(0x2a6fb0);
const UNDERWATER_TINT_MIX = 0.34;
const UNDERWATER_DIM = 0.08;

export function submersionAt(world, pos, inWater, depth = 1.3) {
  if (!inWater) return 0;
  const surface = world.waterSurfaceY(pos.x, pos.z);
  if (surface == null) return 0;
  return Math.max(0, Math.min(1, (surface - pos.y) / depth));
}

export function applySubmersionColor(target, base, frac) {
  const amount = Math.max(0, Math.min(1, frac));
  return target.copy(base)
    .lerp(UNDERWATER_COLOR, amount * UNDERWATER_TINT_MIX)
    .multiplyScalar(1 - amount * UNDERWATER_DIM);
}
```

既存の `applyTint()` もこの共通関数を使う。第1〜3章で用いていた強い補正（青色混合 `0.62`、減光 `0.22`）から、青色混合 `0.34`、減光 `0.08` へ弱める。

### 3.4 描画順と水面

`src/entities/rig.js` では、次の描画順へ変更する。

- 人間型の頭画像: `renderOrder: 14` → `1`
- 人間型の胴体画像: `renderOrder: 12` → `0`
- `MonsterSprite` の画像: `renderOrder: 1` を設定
- 水面: 現状の `renderOrder: 2` を維持

`src/world/mesher.js` の水面は次の値へ変更する。

```js
opacity: 0.66
```

これにより画像と3D部品の両方が水面より先に描画され、同じ水の覆いを受ける。水面の不透明度を `0.82` から `0.66` へ下げるため、従来見えにくかった手足・装備・モンスターも識別しやすくなる。

### 3.5 主人公・住民・通常モンスターへの適用

- `src/entities/player.js`
  - 個別に書かれた水深計算を `submersionAt()` へ置き換える。
- `src/entities/villagers.js`
  - 通常更新と会話・メニュー停止中の `syncVisual()` の両方で `rig.setSubmersion()` を呼ぶ。
- `src/entities/monsters.js`
  - `MonsterSprite` に `setVisualTint(baseColor, submersion)` を追加して利用する。
  - 毎フレーム直接 `material.color.setHex()` する処理を、基本色と水中色を順に合成する `updateWaterAppearance(world)` へ置き換える。
  - 被弾中は赤、通常時は `def.tint` を基本色とする。
  - 通常更新と停止中の `syncVisual()` の両方で水中表示を更新する。
- `src/main.js`
  - 停止中のモンスター `syncVisual()` に `this.world` を渡す。

### 3.6 第4〜5章固有のグロム

第4〜5章の `src/entities/dragon.js` にあるグロムは、第1〜3章にはない複合リグである。

- 胴体と頭: `MonsterSprite` の画像
- 首と尾: 3D球体メッシュ
- 翼: 3Dメッシュ
- 火炎: 3Dスプライト／パーティクル

`MonsterSprite.renderOrder = 1` はグロムの頭・胴体画像にも共通適用される。ただし、グロム全体へ水中色を適用する場合は、画像だけでなく首・尾・翼にも同じ `applySubmersionColor()` を使わなければ、今回と同じ不統一を再発させる。

グロムは通常の `Entity` ではなく `DragonBattle` が位置を管理しており、現行の戦場では水中へ入る想定がない。このため移植時には次のどちらかをコードとテストで明確にする。

1. **推奨:** `DragonRig.setSubmersion(frac)` を実装し、画像・首・尾・翼を一括補正できるようにする。`DragonBattle` 側では実際に水面下へ入った場合だけ値を渡す。
2. 現行仕様としてグロムが水中へ入らないことを保証し、水中補正の実行対象外とする。ただし画像の描画順は通常モンスターと統一する。

第1〜3章の `monsters.js` にはクラーケン触手用の3D処理が含まれるが、第4〜5章には同じ `tentacle` プロパティがない。ファイル全体や触手固有処理をコピーせず、標準モンスター処理とグロム固有処理をそれぞれ第4〜5章の構造へ合わせて移植する。

死亡した頭の灰色 `0x777777`、色替えモンスターの `def.tint`、被弾時の赤色が水中補正後も維持されることに注意する。

### 4.2 水中描画

`dqb3-tsugumono-ch1-3/tests/e2e/underwater-visuals.test.mjs` を土台に、第4〜5章向けへ変更する。

推奨する対象:

- 人間型: 主人公とベルクなど第4章住民
- 非人間型画像: `iron_scorpion` または `lava_lizard`
- 人間型3D部品: 手足と装備
- グロム: `DragonRig` に水中対応を実装する場合のみ、頭・胴体画像と首・尾・翼の全材料

確認内容:

- 水面の不透明度が `0.66` である。
- 頭・胴体・モンスター画像の `renderOrder` が水面より小さい。
- 人間型の画像、手足、装備の全対象色が水中で変化する。
- 住民と通常モンスターにも同じ水中補正が掛かる。
- 被弾色と固有色を水中補正が上書きせず、基本色へ重ねている。
- 停止中のカメラ回転でも水中表示が維持される。
- グロムを対応対象にする場合、画像と3D部品の全対象へ同じ補正が掛かる。
