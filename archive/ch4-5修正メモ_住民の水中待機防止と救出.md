## 2. 移植A: 平時の水中待機防止（水に落ちたら持ち場へ戻る）

### 2.1 問題

`src/entities/villagers.js` の徘徊分岐は、水中にいても通常の抽選
（65%で `pickWanderTarget`、35%で待機）を続ける。徘徊先の抽選は水を避けるが、
**すでに水中にいる住民を陸へ戻す力は無く**、待機を選ぶと水中で立ち泳ぎのまま止まる。

### 2.2 実装（移植時の知見反映済み）

第1〜3章と同じく、徘徊分岐（最後の `else`）に水中判定を追加する。
第4〜5章の同分岐は `villagers.js` の `update()` 末尾近く
（`ctx.farmWork && this.id === "mina"` の次の `else`）にある。

**移植時の知見**: 判定は `this.inWater` 単独では不十分だった。北岸の浜には
波打ち際に「水没した濡れた砂」（`terrainSurfaceY <= WATER_LEVEL` だが水ブロックが
無い列）があり、水から上がった住民がそこで立ち止まってしまう。
「水中または水没地形の上」を表す `wetZone` を判定に使う（救出処理と共有）。

```js
    } else {
      this.rig.setTool(null);
      this.mealSeat = null;
      if (wetZone) {
        // 水に落ちたら立ち泳ぎで待機せず持ち場へ戻る。水から上がっても波打ち際の
        // 水没地形（濡れた砂）の上で立ち止まらず、乾いた陸まで歩き切る。
        // 峠のルーティングを経由するので、水に詰まっている住民も自力で上陸できる。
        this.moveTarget = null;
        desired = this.home;
      } else {
        if (this.thinkTimer <= 0) {
          this.thinkTimer = 3 + Math.random() * 4;
          this.moveTarget = Math.random() < 0.65 ? this.pickWanderTarget(ctx.world) : null;
        }
        desired = this.moveTarget;
      }
    }
```

`desired = this.routeViaPass(desired)` は既存のまま後段で適用されるため、
持ち場が峠の向こうでも正しく経由する。

ベルク（炉）・ロク（坑道）・カヤ（鉄鍋）・ミナ（畑）の持ち場分岐は、
目的地が常に陸上の作業場なので追加処理は不要（水中にいても作業場へ直進し、
歩けない場合は移植Bの救出が拾う）。

## 3. 移植B: 水中スタックの救出テレポート（最終保険）

### 3.1 問題

崖の海岸線（火山斜面が海へ落ち込む地形）、水門・導水路のくぼみ、
プレイヤーが掘った水場などでは、直進＋段差1ジャンプの住民が
水中から自力で登れず物理的に詰まり得る。経路の目標だけでは救えない。

### 3.2 実装（移植時の知見反映済み）

`Villager.update()` の倒れ（`down`）判定の直後に、水中滞在タイマーを追加する。

**移植時の知見**: タイマーの条件を `this.inWater` 単独にすると機能しない。
壁に当たった住民はジャンプを繰り返し、跳ねた一瞬だけ `inWater` が false になって
タイマーが毎回リセットされ、8秒に到達しない（北岸の崖海岸——海底面3から岸5への
2段差——で実測）。「乾いた陸に立つまで」を積算対象にする。

```js
    // 水中（または水没した波打ち際）に長く留まったら、最寄りの乾いた床へ
    // 救出する。崖の海岸線では水際から陸へ2段以上の段差があり自力で登れない。
    // ジャンプで一瞬水から出ても諦めないよう、乾いた陸に立つまで時間を積算する。
    const wetZone = this.inWater || ctx.world.terrainSurfaceY(this.pos.x, this.pos.z) <= WORLD.WATER_LEVEL;
    if (wetZone) {
      this.waterT += dt;
      if (this.waterT > 8) {
        this.waterT = 0;
        const spot = this.findRescueSpot(ctx.world);
        if (spot) {
          this.pos.set(spot.x, spot.y + 0.1, spot.z);
          this.vel.set(0, 0, 0);
          this.moveTarget = null;
        }
      }
    } else {
      this.waterT = 0;
    }
```

コンストラクタで `this.waterT = 0` を初期化する。

`findRescueSpot` はクラスメソッドとして追加する（第1〜3章の実装をそのまま使える）。

```js
  // 水中救出の行き先: 自分のまわりを近い順に走査し、水没していない床を返す。
  findRescueSpot(world) {
    for (let r = 2; r <= 10; r += 1) {
      for (let a = 0; a < 16; a += 1) {
        const ang = (a / 16) * Math.PI * 2;
        const x = Math.floor(this.pos.x + Math.cos(ang) * r) + 0.5;
        const z = Math.floor(this.pos.z + Math.sin(ang) * r) + 0.5;
        const y = world.terrainSurfaceY(x, z);
        if (y > WORLD.WATER_LEVEL) return { x, y, z };
      }
    }
    return null;
  }
```

### 3.3 注意点

- 判定は8秒（ゲーム内実行時間）。移植Aにより通常は数秒で自力上陸するため、
  テレポートが発火するのは本当に詰まった場合だけになる。
- 走査半径は10マス。北岸の沖に流されても、南北どちらかの岸か浅瀬に届く。
- 倒れ演出（`stayDown`）中の住民は `down` 分岐で早期リターンするため対象外。
  水中で倒す演出を将来入れる場合もこの順序なら干渉しない。
- セーブ形式・`GEN_VERSION` は変更しない。
