## 1. 目的と現在の確認結果

第1〜3章で見つかり修正済みの次の2点を、第4〜5章にも反映する。

1. 初登場キャラクターの画像取得が一時的に失敗した場合、ページを再読み込みしなくても自動復旧する。
2. 設計図セルの現在ブロックが水の場合も、ゴーストをクリックして必要資材を設置できる。

第4〜5章側を確認したところ、両方とも修正前の共通コードが残っている。

- `src/entities/rig.js` の `loadSheet(url)` は、`TextureLoader.load(url)` が返した未読込テクスチャを
  即座に `sheetCache` へ保存し、失敗時の処理・再試行がない。
- `src/main.js` の `pickGhostCell()` は `B.AIR` のセルだけをクリック候補へ入れ、`B.WATER` を除外している。
- 一方、`src/game/blueprints.js` の障害物判定は `B.AIR` と `B.WATER` の両方を非障害物として扱う。

現行ワールド（`GEN_VERSION: 6`）を生成し、全11設計図をストーリー上の正規アンカー・基準高さへ

現時点で橋と同じ不具合が必ず発生するわけではない。ただし、泉の祭壇と水門 `spring_works`、
竹の水路、海岸付近の建築、今後追加される設計図やプレイヤーが編集した地形では同じ問題が
表面化し得る。共通処理の整合を取る低リスクな予防修正として移植する。

## 2. 修正A: キャラクター画像の読込失敗を自動復旧

### 2.1 問題

`src/entities/rig.js` の現在の `loadSheet(url)` は、画像の読込完了前にテクスチャをキャッシュする。
画像要求が一度失敗すると、空のテクスチャがそのページを開いている間ずっと残り、再要求されない。

住民の場合、名前・「！」・影・手足は画像シートと別に生成される一方、頭と胴体はシート画像を使う。
そのため失敗時には、名前と手足だけが見え、頭と胴体が消えた状態になる。セーブ後にページを再読込すると
モジュール内のキャッシュが作り直されるため、次の要求が成功すれば正常表示へ戻る。

第4〜5章では同じ `loadSheet()` を次が共有しているため、住民だけでなく広く効果がある。

- `HumanoidRig`: 主人公、ミナ、ゴンタ、ワタリ、ベルク、ロク、カヤ、ナギ、ヨモギなど
- `MonsterSprite`: 通常モンスター
- `dragon.js` から `MonsterSprite` を使うグロムの胴体・頭

### 2.2 決定仕様

1. 正常時は従来どおり画像要求を1回だけ行う。
2. 失敗時は400ms後、さらに失敗した場合は1.2秒後に再試行する。
3. 初回を含め最大3回で自動試行を打ち切り、無限再試行しない。
4. 再試行に成功した画像は、すでに画面に存在するキャラクターへ反映する。
5. 3回すべて失敗した場合はコンソールへエラーを残す。後で同じ画像を使う新しいリグが
   作られた場合は、新しい試行系列を開始できる状態に戻す。
6. セーブ形式・ワールド生成バージョンは変更しない。

### 2.3 実装上の重要点

**失敗時に `sheetCache.delete(url)` を行い、新しい `THREE.Texture` へ交換するだけでは不十分。**
既に生成された頭・胴体・モンスタースプライトは、失敗した古いテクスチャの `Source` を参照し続けるため、
新しいテクスチャの読込に成功しても画面上の既存キャラクターは復旧しない。

第1〜3章の実装と同じく、URLごとに「受け皿となる安定した `THREE.Texture`」を先に作り、
各試行で取得した画像だけをその受け皿へ入れる。

```js
const SHEET_RETRY_DELAYS_MS = [400, 1200];
const SHEET_MAX_ATTEMPTS = SHEET_RETRY_DELAYS_MS.length + 1;

// configureSheet(texture): filter / mipmap / wrapping / colorSpace を従来どおり設定

function requestSheet(url, entry) {
  entry.attempts += 1;
  textureLoader.load(
    url,
    (loaded) => {
      // entry.texture は既存の clone と同じ Source を共有している。
      entry.texture.image = loaded.image;
      entry.texture.needsUpdate = true;
      entry.loaded = true;
    },
    undefined,
    () => {
      const retryDelay = SHEET_RETRY_DELAYS_MS[entry.attempts - 1];
      if (retryDelay !== undefined) {
        entry.retryTimer = setTimeout(() => {
          entry.retryTimer = null;
          requestSheet(url, entry);
        }, retryDelay);
        return;
      }
      entry.attempts = 0;
      console.error(`Character sheet load failed after ${SHEET_MAX_ATTEMPTS} attempts: ${url}`);
    },
  );
}
```

`loadSheet(url)` は `sheetCache` に単体のテクスチャではなく、次のエントリを保持する形へ変更する。

```js
{ texture, attempts: 0, retryTimer: null, loaded: false }
```

第4〜5章の `rig.js` は武器モデルなどが第1〜3章と異なるため、ファイル全体を上書きしない。
上部の `textureLoader` / `sheetCache` / `loadSheet` 周辺だけを参照実装に合わせる。

## 3. 修正B: 水中の設計図セルをクリック可能にする

### 3.1 問題箇所

`src/main.js` の `pickGhostCell()` にある次の判定が、水中セルをレイキャスト対象から除外している。

```js
if (this.world.get(cell.x, cell.y, cell.z) !== B.AIR) continue;
```

設計図ゴースト自体は水中にも表示でき、`BlueprintManager.refresh()` は水を障害物とみなさず、
通常のブロック設置も水を置換できる。クリック候補の収集だけが水を拒否するため、必要資材を持っていても
水中のゴーストをクリックして自動設置できない。

### 3.2 実装

第1〜3章と同じ2行の変更を行う。

```js
const current = this.world.get(cell.x, cell.y, cell.z);
if (current !== B.AIR && current !== B.WATER) continue; // obstacle / filled
```

これにより次の関係が統一される。

- `B.AIR`: 未設置セルとしてクリック可能
- `B.WATER`: 水を必要資材へ置換する未設置セルとしてクリック可能
- その他のブロック:
  - 要求ブロックと一致すれば完成済み
  - 一致しなければ障害物であり、クリックによる自動上書きはしない

### 3.3 第4〜5章用の回帰テスト

第4〜5章には現在 `tests/e2e/blueprint.test.mjs` がなく、`bridge` 設計図も存在しないため、
第1〜3章のテストをそのままコピーしてはいけない。専用の `blueprint.test.mjs` を新規作成するか、
小さな独立テストとして追加する。

現行の正規配置では水と重なる設計図セルが0件なので、テスト内で制御された水セルを作る。
推奨手順:

1. `spring_works`（泉の祭壇と水門）を既知のアンカー・基準高さで起動する。
2. 資材が通常ブロックであるセル（例: 石の基礎セル）を1つ選ぶ。
3. テスト内だけで、そのセルの現在ブロックを `B.WATER` にする。
4. 他のゴーストを非表示にし、選んだセルを画面座標へ投影する。
5. プレイヤーを到達範囲へ移動し、必要資材を持たせる。
6. `page.mouse.click()` で実際にゴーストをクリックする。
7. 次を確認する。
   - 水中セルが `aimGhost` になる。
   - 水が設計図の要求ブロックへ置き換わる。
   - 対応資材が1個減る。

併せて、石・土などの誤ブロックがあるセルは従来どおり障害物のままで、クリックによる自動上書きが
行われないことを維持する。
