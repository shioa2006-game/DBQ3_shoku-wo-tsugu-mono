# 職をつぐ者 〜ジパング復興編〜

ドラゴンクエストビルダーズへのオマージュとして制作した、ブラウザで遊べる
「ブロックメイクRPG」の MVP です（three.js + Vite / WebGL）。

『ドラゴンクエストIII』のゾーマ討伐後、再び魔物があふれる上の世界が舞台です。
ダーマ神殿の襲撃で多くの職業の書が失われ、神官見習いの少年シオンは一冊の「職業の書」を携えて脱出します。
漂着したジパングで、その話す書に導かれ、町づくりを通じて人々の職と暮らしを取り戻していきます。
物語の現状は [共通ストーリー資料](../docs/story/README.md) を参照。実装済みの[第1章](../docs/story/implemented/chapter1.md)・[第2章](../docs/story/implemented/chapter2.md)・[第3章](../docs/story/implemented/chapter3.md)をまとめています。編名はタイトルから結末まで「ジパング復興編」に統一しています。台詞の修正内容は[不整合一覧](../docs/story/inconsistencies.md)に記録しています。

## 起動方法

```powershell
npm.cmd install
npm.cmd run dev
```

表示されたローカルURL（通常 `http://localhost:5173/builder_sprite_lab/`）をブラウザで開いてください。
Windows では `start-dev.bat` でも起動できます。[親リポジトリ](../README.md)内の配置で開発してください。建築・所持品・職業の書・防衛・保存の共通処理は [game-shared](../game-shared/) を参照し、`npm run build` でこの編の `dist/` に含まれます。公開は[共通トップの手順](../portal/README.md)を参照してください。


## 人と設備の選び方

右クリックはカーソルで指した人や収納箱などを操作します。地面をクリックしても、近くの人との会話には切り替わりません。Fキーは、マウスの位置に関係なく主人公の正面の近い人・設備を選びます。操作できる対象には枠と「収納箱を開く」「ミナと話す」などの案内が出ます（右クリックは金色、Fは水色。同じ対象なら1つにまとめます）。壁の向こうや手が届かない対象は選びません。

## テスト

```powershell
npm.cmd run test:ci
npm.cmd run test:e2e
```

ヘッドレス Chrome で第1章ストーリー全体・設計図建築・セーブ/ロードの回帰テストを実行します
（`tests/`。Chrome/Chromium は自動検出、見つからない場合は環境変数 `PW_CHROMIUM_PATH` で
実行ファイルを指定）。`test:ci`は高速サブセット、`test:e2e`は全回帰テストです。

## キャラクター画像

CH1～CH3の人型7人・基本モンスター5種は、Storybook Character Studioのコード生成画像を本編で使用します。ボス3体も対応するモンスター画像を共用します。頭・胴の分離、リグ設定、更新方法は [キャラクター移植記録](docs/CHARACTER_ART.md) を参照してください。

## アイテムアイコン

インベントリ・ホットバー・クラフト一覧・設計図・地面のドロップのアイコンは、Studioの [item-icons](../Storybook_Character_Studio/prototypes/item-icons/README.md) でコードから描いた16×16のドット絵です。`assets/items/item_icons_16.png`（全アイテムを並べた1枚）と `item_icons_16.json`（アイテムID→位置）を読み込み、2倍の32pxで表示します。画像が読めないときだけ、従来のブロックの模様・emoji（`items.js` の `tile`・`icon`）で表示します。

アイコンを直すときはStudioの `icons.mjs` を編集し、Studioで `npm.cmd run export:items -- --preview-game` を実行します。ゲーム側の画像を直接編集しないでください。

## 設置物の3D

すべての設置物（かかし・たいまつ・わらのベッド・鳥居・木の扉・作業台・職業の祭壇・とげ罠・柵・収納箱・かまど・ちゃぶ台・舵輪・職業の旗・稲・わら草・きのこ・魚のかげ）は、Studioの [props-3d](../Storybook_Character_Studio/prototypes/props-3d/README.md) の原本から書き出した `src/world/prop-models.js` で作ります。基本形状に黒い輪郭線を付け、木・石・わらの面にはブロックの模様を貼っています。とげ罠は石のとげをスライムゼリーで固めた形です。柵は隣の柵・扉へ横木を渡し、かまどの焚き口と収納箱の留め具は手前（+z）を向きます。魚のかげは水面のすぐ上のマスに置くので、`src/world/mesher.js` はその下にも水面を描きます（描かないと水面に穴があき、砂の底が見える）。

形を直すときはStudioの `models.mjs` を編集し、Studioで `npm.cmd run export:props -- --preview-game` を実行します（第1～3章と第4～5章の両方へ書き出します）。`prop-models.js` は直接編集しないでください。今の本編の形と新しい形は、開発サーバーの `/builder_sprite_lab/prototypes/props-3d/` で並べて比べられます（第4～5章だけの設備は第4～5章の開発サーバーで比べる）。

## ストーリームービー

物語の節目に、SVGで描いたストーリームービーが全画面で流れます：「はじめから」の後のプロローグ、第1章の結び（社で祈った後）、第2章の結び（田んぼ防衛戦の勝利会話の後）、旅立ち（ワタリに旅立ちを告げた後。クリア後の再演でも）、農民・料理人・船乗りの書の復活。クリック・Space・Enter で次の場面、Esc・「スキップ」で終わります。再生中はゲームの世界が止まります。

ムービーの原本はStudioの [story-movies](../Storybook_Character_Studio/story-movies/) で、Studioの `npm.cmd run sync:movies` で `assets/movies/` へ写します（直接編集しない）。読み込めないときは流さずに進みます（書の復活だけは今までの小窓）。全画面で文字が流れる章末は2026-11-08に削除し、章末はムービーだけです（全文は[削除した文字の章末](../docs/story/reference/removed-text-endings.md)に記録）。プロローグを最後まで見たときは、導入会話の冒頭の語り（ムービーと同じ内容）を省きます（[不整合一覧のSTORY-008](../docs/story/inconsistencies.md#story-008)）。テストでは `tests/helpers.mjs` の `openGame` がムービーを止め、`tests/e2e/movies.test.mjs` だけがムービーを流します。

| --- | --- |

| `M` | サウンド ON/OFF |
| `Esc` | ポーズ（セーブ） |

## 第1～3章の流れ

1. 第1章「漂着の浜」: 小屋と畑を作り、収穫で農民の書を復活させる。旗を守り、職業の社で祈ると章末のムービーが流れる。
2. 第2章「荒れた田の村」: 第1章完了の翌日、南への橋と田・食堂を復旧する。料理人の書を復活させ、田を守る。
3. 第3章「旅立ちの港」: 船乗りワタリと桟橋・灯台・船を再建する。授職の儀とクラーケン戦を経て出航し、「ジパング復興編・完」となる。

第1章の `POSTGAME` は第2章への章間状態です。第3章クリア後は `CH3_DONE` の同じ島で自由建築を続けられます。第4章は別ゲームの固定初期状態から開始し、このゲームのセーブや所持品を移送しません。

昼夜サイクルがあり、拠点の外では常時モンスターがわきます（夜は増加）。
倒すと素材を落とし、装備強化（こん棒→石の剣→銅の剣、こうもりのマント等）に使えます。
セーブは localStorage（オートセーブ＋ポーズ画面から手動）。

## 実装の構成

```
src/
├─ main.js            ゲーム統合（ループ・入力・アクション・カメラ）
├─ core/              input.js（キー＋マウス）, utils.js（RNG・8方向変換）
├─ world/
│   ├─ blocks.js      ブロック定義＋テクスチャアトラス（全てコード生成）
│   ├─ world.js       ボクセルデータ・島の地形生成・DDAレイキャスト・セーブ差分
│   ├─ mesher.js      チャンク単位のメッシュ結合（不可視面カリング）
│   ├─ props.js       設置物の配置・動き（扉・炎・旗・稲の揺れ）＋光源プール
│   └─ prop-models.js 作り直した設置物（Studio原本の書き出し。直接編集しない）
├─ entities/
│   ├─ rig.js         2.5Dキャラリグ（8方向スプライト＋3D手足）※試作ラボから移植
│   ├─ player.js      主人公（自由移動・ジャンプ・水泳・装備）
│   ├─ villagers.js   住民4人（追従・農作業・戦闘参加・会話）
│   ├─ monsters.js    スライム／おおこうもり／ボス（8方向ビルボード2ポーズ切替）
│   └─ entity.js      AABB×ボクセル物理・アイテムドロップ
├─ game/              items.js, quests.js, blueprints.js, defense.js,
│                     daynight.js, save.js, sfx.js（WebAudio合成SFX）,
│                     bgm.js（通常/ボスの2曲をクロスフェード）
└─ ui/ui.js           HUD・会話・メニュー・設計図パネル・タイトル
```

### キャラクター表現（2.5D）

- **人間型**（主人公＋住民4種）: 頭と胴は 8方向スプライトシート（4×2, 128px セル）の
  UV窓切り出しを薄い Box の前面に貼り、腕・脚・道具は 3D トゥーンメッシュ。
  歩行スイング・攻撃モーション・向きごとの手足レイアウトは試作ラボの調整値をそのまま使用。
- **非人間型**（スライム・おおこうもり）: 8方向ビルボードで `idle_a` / `idle_b` の
  2ポーズを交互切替。スライムは跳ねの伸縮、こうもりは浮遊バウンスを追加。
  ボスは同シートの色替え＋拡大で表現。
- カメラは固定クォータービューを45°刻みで回転（キャラが8方向画像のため8方向限定）。
  視線が木の葉などで遮られると自動でズームインします。

### ワールド

- 64×64×24 のフルボクセル。掘削・設置自由（銅鉱石は石のハンマーが必要）。
- ブロックテクスチャ・UIはコード生成。画像アセットはキャラクターとアイテムアイコン（Studioのコード生成画像）。
- 島の地形（浜・草原・西の森・北の火山風の山・拠点用の平地）はシード固定の手続き生成。
  セーブには生成後の差分のみを保存します。

## 既知の改善余地

- 住民の移動は直進＋段差1マスのジャンプのみで、一般的な経路探索は持たない。
  海を渡る移動には個別のルール（橋・桟橋の経由、水没マスを避けた徘徊、
  水に落ちた場合の復帰と救出）で対応しているため、複雑な地形では
  引っかかることがある
- 防衛戦の敵AIは守る対象へ直行する型。柵・扉は攻撃で壊されるが、地形は壊さない
- 効果音は WebAudio の簡易合成（音声ファイルなし）。BGMは通常時とボス戦の2曲のみ
- モバイル（タッチ）未対応
