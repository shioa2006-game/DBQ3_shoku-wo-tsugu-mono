# 実装の依頼：第6～7章「ダーマ再興編」のゲームを完成させる

2026-11-14作成。ストーリー・キャラクター・ショートムービーの準備が終わった時点で、Fable 5.2 に第6～7章の実装を任せるための依頼文です。作業の途中で読み返せるよう、ここに置いています。

## 目的

ブラウザーで遊ぶブロックメイクRPG『職をつぐ者』の第6～7章（ダーマ再興編）を、`dqb3-tsugumono-ch6-7/` に新しいゲームとして作り、最初から最後まで遊べる状態にしてください。

ストーリー・キャラクター・ショートムービーは準備済みです。台詞・マップ・アイテム・武器・数値などのゲームの中身は、あなたが自律的に設計して構いません。

## 必ず守ること（ストーリーの決定）

物語の筋・人物の役割・敵の構成は、上の資料のとおりに作ってください。共通設計の「決定した制作方針」の表は、遊びに関わる項目（防衛対象の祭壇、敗北時の復元、勝利時の損傷の引き継ぎ、合図で次の波へ進むことなど）も含めて決定済みとして従ってください。特に次の点は見落とさないでください。

- 章名は第6章「よみがえるダーマ神殿」、第7章「三つ首の空」。編名は「ダーマ再興編」。
- 舞台は、一方が海に接し、奥へずっと山が続く島。旧ダーマ神殿を元の場所に再建する。
- 敵は8種。岩角ヤギ・山ねずみ（第6章の山道）、小岩ガニ・洞窟こうもり（採石洞）、大岩ガニ（第6章のボス）、ガーゴイル・岩砕きのガーゴイル（第7章の防衛）、三頭魔竜ヴァルガ（第7章のボス）。糸吐きグモと岩砕きの石兵は出さない。
- ガーゴイル軍はヴァルガの先兵。海を越えて飛来し、防衛線の手前に着地してから地上を進む。3波の後に、ヴァルガ本人が海の向こうから来る。
- 初襲来でヴァルガは自ら名乗り、自分がダーマを焼いたと告げる。シオンはその言葉で、旧神殿を壊した竜だと知る。
- 初襲来の後、大屋根の一部は必ず傷ついている（アサギが自分から補修に取りかかる場面につなぐため）。
- 決着では、三つの頭を倒すとヴァルガは黒い霧へ崩れて消える。黒鱗など何も残さない。
- 結末では、要石の祭壇がシオンの写しに力を宿すので、原本が旅立った後もスズハが授職を続けられる。最後の出航で、旅の4人の船がピノをジパング、ベルクを火山島へ送り届けてから、世界中の職業の書を探す旅へ進む。
- 話す職業の書の内部IDは `builder` のまま。新しい書は復活しない。主要人物の授職と継承は、物語のイベントとして描く。
- 第1～5章の実装済みの台詞・出来事と矛盾させない。たとえば、シオンは神殿にいた人々の中で唯一の生存者。プロローグでシオンは三つ首の竜を見ていない。

## あなたに任せること

次のことは、ストーリーと矛盾しない範囲で自由に設計してください。

- 台詞の全文
- マップの寸法・方角・地形・麓の集落の配置、採石洞の構造
- アイテム・素材・武器・防具・料理・レシピ、設計図の寸法と資材数
- 敵とボスの数値・行動・出現数、3波の具体的な構成
- 罠とボウガンの仕様、手動の対空射撃の操作、修復ガイドの仕組み
- プレイヤーが倒れたときの扱い、航海の時間の表し方、UI、クリア後の遊び方

共通設計の「実装担当へ委ねる設計」と「残る設計事項」の大半は、ここに入ります。決めたことは、後述の設計資料に記録してください。

## ムービーとキャラクター

- **ムービー**: Studio の `story-movies/` に5本あります（M10 `ch6-arrival`、M11 `ch6-roof-light`、M12 `ch7-three-heads`、M13 `ch7-flame-holds`、M14 `ch7-unseen-books`）。第1～5章と同じく `game-shared/story-movies.mjs` で再生します。`story-movies/game-targets.mjs` に第6～7章の書き出し先を加え、`npm.cmd run sync:movies` で `assets/movies/` へ写してください。入る場所は `chapter6-7-movies.md` の表のとおりです。
- **会話との重なり**: 字幕と同じ文を、前後の会話で続けて流さないでください。ムービーを飛ばしたときや読み込めないときにも話が通じるよう、要点（ヴァルガの名乗りなど）は会話にも用意し、最後まで見たときだけ省きます（`inconsistencies.md` の STORY-008 と同じ方式）。
- **神殿の形はムービーに合わせる**: 崩れた神殿跡と再建後の外観（Studio の `story-movies/shared/temple.py`）を、設計図の手本にしてください。島の向き・寸法・坂道・桟橋・集落は、ゲームで決めて構いません（`chapter6-7-scenario.md` の分担表）。ムービーの島と大きく違う形にしたときは、どこが違うかを設計資料に記録してください（ムービーの描き直しは別の作業）。
- **キャラクター**: 人物と敵の原本は Studio の `prototypes/` にあります（スズハ・アサギ・ガンゾウ、ガーゴイルと岩砕きのガーゴイル、小岩ガニ、岩角ヤギ、ヴァルガ `varuga-8dir` など）。Studio の `AGENTS.md` の手順で書き出し、`prototypes/shared/game-targets.mjs` に第6～7章を加えて写してください。山ねずみと洞窟こうもりは既存の造形の色替え、大岩ガニは小岩ガニの大型版です。Studio の作画（`character.mjs`）は、移植のためにやむを得ない調整以外は変えないでください。

## 作業のルール

- 既存の2編（`dqb3-tsugumono-ch1-3`、`dqb3-tsugumono-ch4-5`）の動作・セーブ・相対パスを壊さないでください。第6～7章は、最初に起動する前に、専用のセーブキー（例：`shoku_wo_tsugumono_dharma_save_v1`）、Vite の base、テストのURLを決めてください。既存2編のセーブが残る同じブラウザーでも、互いに読み書きしないようにします。
- `game-shared/` や Studio の共通部品を変えるときは、既存2編と Studio のテストも通してください。
- **テスト**: コードを変えたら `npm.cmd run test:ci`（ビルドを含む）。章の進行・戦闘・セーブに関わるときは `npm.cmd run test:e2e` も実行します。Studio を変えたら、Studio で `npm.cmd test`。既存2編のテストは同じ既定ポート（4174）を使うので、順番に実行してください。第6～7章のテストは、別のポートにしても構いません。
- **Git**: 作業の区切りごとに、対象のファイルを指定して、日本語のメッセージでコミットしてください。push・force push・履歴の書き換えはしないでください（push はユーザーが頼んだときだけ）。他の作業の未コミットの変更を混ぜないでください。`node_modules/`、`dist/`、`work/`、テストのスクリーンショットはコミットしません。
- **公開**: 共通トップ（`index.html`）の準備中ボタン、ポータル、`.github/workflows/pages.yml` への第6～7章の追加は、ゲームが完成した後、ユーザーに確認してから行ってください。
- 既存のサーバーやブラウザーを、無断で止めないでください。

## 進め方

次の段階で進め、各段階の終わりにテストを通してコミットしてください。段階と段階の間で、ユーザーの確認を待つ必要はありません。

1. **計画**: 資料を読み、`dqb3-tsugumono-ch6-7/docs/DESIGN.md`（名前は自由）に全体の設計を書く。マップ、章の進行とステージ、アイテムとレシピ、敵とボス、防衛、セーブ、ムービーの入る場所を含める。
2. **土台**: 第4～5章から必要なコードとテストを写し、セーブキー・base・テストの設定を変えて、ゲームが起動してテストが通る状態にする。
3. **素材**: キャラクターとムービーを Studio から写す。
4. **第6章**: 導入（M10）から、神殿の再建、採石洞と大岩ガニ、要石の切り出しと搬出、ピノの招聘、最初の授職、章末（M11）まで。
5. **第7章**: ガーゴイル軍の3波と、その間の修理と補給。ヴァルガの初襲来（M12）、ベルクの招聘と大型対空ボウガン、最終決戦（M13）、継承と結末（M14）、クリア後まで。
6. **仕上げ**: 通しの進行、資材が足りないところからの復帰、敗北した後の再挑戦、途中のセーブとロードを e2e テストで確かめる。既存2編のセーブが残る状態で第6～7章を始め、既存2編も元どおり再開できることを確かめる。

## ストーリーとの食い違いを見つけたとき

ストーリー資料の筋は変えずに進めてください。食い違いや、資料どおりには作れない点は `docs/story/inconsistencies.md` に記録し、最終報告で知らせてください。筋そのものを変える必要があると判断したときは、その時点で作業を止めて、ユーザーに確認してください。

実装が終わったら、第1～5章と同じ形で `docs/story/implemented/` に第6章・第7章の記録（実装に基づく出来事・ステージ・セーブ）を作り、資料の入口の状態を「実装済み」に更新してください。
