# 海を越えて ― 火山島編の始まり（SVGストーリームービー試作・M5）

『職をつぐ者』火山島編（第4～5章）の最初に入れる、約29秒・全5場面のストーリームービーの試作です。**Studio内の試作で、ゲーム本編には組み込んでいません。** 採用と移植はユーザーが確認してから決めます。

- 確認URL: Studioを起動（`npm.cmd start`）して http://127.0.0.1:8081/story-movies/ch4-arrival/ 。[ムービーの一覧](../index.html)（`/story-movies/`）からも開けます。
- 計画: [SVGストーリームービーの挿入計画](../../../docs/story/planned/story-movies.md) の M5（優先度A）。物語は [第4章の記録](../../../docs/story/implemented/chapter4.md)。
- 場面ごとの時間・カメラ・字幕・絵の内容: [絵コンテ](reference/storyboard.md)

火山島編は第1～3章とは別のゲームとして始まり、プロローグがありません。初めて遊ぶ人にもシオンたちのことが分かるよう、プロローグと第3章の結末（M4）の絵を「思い出の額」に入れて短く振り返り、長い航海の後に煙を上げる火山島へ着くところまでを見せます。

イラストはすべてコードで描いたSVGで、音声はありません。非公式ファン企画用です。

## 再生と操作

プロローグ・M4と同じ再生エンジン（[`../shared/engine.py`](../shared/engine.py)）です。「ムービーを見る」で再生し、クリック・タップ・Space・Enter で次の場面へ（第5場面の1回目はタイトルまで）、「スキップ」・Esc で終了画面へ、「もう一度見る」で最初から。確認用のURLパラメータは `?autoplay=1`・`?from=3`・`?still=4&t=4200`・`?reduced=1`。

## 生成する

Studioのルートで実行します。Node.js 18以上と Python 3.9以上（標準ライブラリだけ）が必要です。

```powershell
npm.cmd run build:movie -- ch4-arrival
```

1. [`../shared/cast.mjs`](../shared/cast.mjs) が、登場人物（`cast.mjs` の一覧：四人の正面と背面）の頭・胴のSVGを `parts/cast.json` へ書き出します。
2. `src/build.py` が、5場面のSVGとストーリーデータを共通の再生エンジンで `index.html` にまとめます。乱数は固定シードなので、何度実行しても同じ内容になります。

思い出の額（場面①・②）は、プロローグ（`../prologue/src/scenes_b.py` の `scene4()`）と第3章の結末（`../ch3-departure/src/scenes.py` の `scene1()`・`scene2()`）の場面を、生成のたびにそのまま縮めて入れます。そのため、プロローグやM4の絵を直したら、このムービーも生成し直します（`npm.cmd test` は食い違いを見つけます）。船も第3章の結末の `props.py` のものを使います。

`index.html` と `parts/cast.json` は生成物です。手で直さず、`src/` を直して生成し直します。思い出の額に2本分の場面が入るので、`index.html` は約0.8MBあります。

## 作画上の約束ごと

- 人物の頭・胴は正式デザインの作画コードのまま（2026-11-08に腰まで描くよう直したもの）。ムービーで描くのは手足（色はゲームの3Dリグと同じ）と姿勢だけ。
- 思い出の額の中は、元のムービーの絵を描き直さずにそのまま使う。元の接頭辞（`s4-`・`s1-`・`s2-`）は、この場面の接頭辞の下（`s1-pa-`・`s2-ma-`・`s2-mb-`）に置き換える。プロローグ第4場面の後半（走る背中の近い画）は額では出さない。
- 船はM4と同じ（同じ船で旅を続ける）。夜は帆を月明かりの色に沈め、船尾の灯りをやわらかく光らせる。
- 火山島は黒い岩と赤い火口、灰色の噴煙。第4章の舞台（黒砂の浜・焼けた船着き場・鉱山町）に合わせる。鬼火・魔物・鉱山町の中は描かない（会話とゲームで初めて見せるため）。
- 第4章の導入会話の台詞（ワタリ・ミナ・ゴンタ・シオン・「——だれか、いるの……？」）は字幕にしない。ムービーの後の会話にそのまま残すため。
- id・クラス・アニメーション名には場面の接頭辞（`s1-`～`s5-`）を付ける。位置の動きには `.mv` を付け、モーション軽減時に止める。現れ方（不透明度）は `.mv` の付かない外側の組に分け、止めても絵が残るようにする。

## 確認する

```powershell
npm.cmd test
npm.cmd run test:movie -- ch4-arrival
```

`npm.cmd test` は、人物の部品が作画コードと一致すること、字幕がそれぞれの出どころの文と一致すること、思い出の額に元の場面が入っていること、正式デザインの人物が場面③・④に出ること、id の接頭辞、Pythonでの再生成が同じ内容になることを確かめます。`test:movie` は、空いているポートでStudioのサーバーを起動し、第1～3章のテスト用ブラウザーで実際に再生します（各場面の静止画、自動再生の完走と所要時間、クリックでの送りとタイトルの停止点、スキップ・Esc・再再生、モーション軽減、スマートフォンの縦・横、ページのエラー）。

## ゲームへ移植するときの注意

- 入る場所は、火山島編の「はじめから」の後、`CH4_ARRIVAL` の導入会話（`chapter4.js` の `intro`）の前。
- ムービーを流した後の導入会話では、地の文（「……潮風が、変わった。…」）と、職業の書の振り返りの2行（「思い出すのう…」「本島は…」）を外すか短くする。ワタリ・ミナ・ゴンタ・シオンの台詞と、最後の「——だれか、いるの……？」からのカヤとの出会いは会話に残す。
- 思い出の額に他のムービーの絵を入れているので、移植するときはプロローグ・M4と同じ版の絵を使う。

## 残っている課題

- 音楽・効果音・ナレーションはない。
- 実機（スマートフォン）での滑らかさは未確認。テスト用のブラウザー（ソフトウェア描画）では毎秒25～39コマ程度。場面②はM4の2場面を同時に描くので、いちばん重い（額そのものは動かさず、重なる額だけを短く滑り込ませて軽くしている）。
- 第4場面の四人は後ろ姿で立つだけの姿勢。
