# 8方向キャラクター制作ガイド

主人公・ミナ・ピノの制作で受けた指摘を、次のキャラクターでも使える確認項目にまとめたものです。見た目の基準は元ゲームの画像とユーザーの比較画像です。コード上で左右対称・滑らかでも、元画像の比率やゲーム内の見え方に合っているとは限りません。

## 制作方式と現在の状態

このStudioは、方向ごとのSVGの形をコードで組み立て、PNGへ書き出す方式です。身体の3Dモデルを8方向から撮影する方式ではありません。頭・胴体は画像、腕・脚・道具はゲーム側の3Dリグで表現します。

| 対象 | 現在の出力 | 注意点 |
|---|---|---|
| 主人公・試作07 | 頭と胴が一枚になった8方向シート | 従来の共通シート切り出し方式。ミナのような頭・胴分離は未適用。首周りやスカーフの重複確認は今後も必要 |
| ミナ・試作05 | 頭専用シートと胴体専用シート、比較用合成シート | リグには分離した2枚と `rig-profile.mjs` を渡す。合成PNGだけを移植すると襟の二重表示対策が失われる |
| ピノ・試作01 | 頭専用・胴体専用・比較用合成シート | 最初から首布を胴だけに配置。固有の帽子・短髪・顔比率を作画 |
| イナホ・試作01 | 頭専用・胴体専用・比較用合成シート | 白いコック帽と黒いボブを専用作画。赤い首布と結び目は胴に配置 |
| ゴンタ・試作01 | 頭専用・胴体専用・比較用合成シート | 短い茶髪・太い眉・広めの顎。生成りの襟と緑の服は胴に配置 |
| ジンベエ・試作01 | 頭専用・胴体専用・比較用合成シート | 額を出した白髪・白い眉・年齢を感じる目元と顎。折り襟は胴に配置 |

いずれも試作で、本編への置き換えはまだ行っていません。全キャラクターの制作完了後に移植する方針です。

## 共通ルールの早見表

共通化するのは、原因の切り分け・部品の担当・比較条件・検証手順です。顔の縮小率、首の高さ、肩幅などの数値はキャラクターと方向ごとに決めます。以下の個別事例にある数値は実施済みの設定であり、新規制作の既定値や、再度掛ける補正値ではありません。

| 判断すること | 共通ルール | 修正・保存する場所 |
|---|---|---|
| 顔が大きい | 顔の輪郭と、髪・帽子を含む頭全体を分けて測る。幅と高さも別に判断する | 各 `character.mjs` の対象方向 |
| 縮小の基準 | 顎・耳側など首との接続を保てる点を基準にする。顔全体の大きさを直すときは目・鼻・口・耳も一緒に調整する | 作画のグループ変換。部品の比率自体が違う場合は部品を個別修正 |
| 方向間の違い | 正面・斜め前・真横・斜め後ろ・背面を別々に比較する。対称な作画は反転で揃えた後、実際の左右両方で確認する | 方向別作画と8方向比較画像 |
| 頭と胴の食い込み | レイヤー・切り出しを先に確認し、配置の問題だけをリグで直す | `rig-profile.mjs` と生成マニフェスト |
| 首・襟の二重表示 | 首・襟・服は胴側の担当とし、頭側に混入させない。共通シートではUV重複帯を調べる | 作画レイヤーと読込設定 |
| 装備が顔に重なる | 前後関係・取付・道具の向き・振る軌道を切り分ける。重なりを消すことだけを合格条件にしない | ゲーム側リグと動作検証 |
| 比較と維持 | 元画像と生成画像を同じ条件で並べ、修正対象以外の方向・動作も確認する | 公式比較テスト・修正前後の差分 |

顔の大きさを直すために胴や手足まで縮めたり、頭の間隔を直すために絵の中心を方向ごとにずらしたりしないでください。作画、切り出し、3D配置を一度に動かすと、どの変更が改善につながったか判断しにくくなります。

## 1. 描く前に元画像を観察する

最初に正面・斜め前・横・斜め後ろ・背面を並べます。大きな輪郭 → 部品の位置と比率 → 重なり → 細かな線や陰影の順で合わせます。拡大画像とゲーム内の通常サイズを併用してください。

| 部位 | 比較する基準 |
|---|---|
| 顔 | 顔幅・高さ、頬の最大幅の位置、顎の幅と高さ、耳の高さ |
| 目 | 顔幅に対する目の幅、目の高さ、左右の間隔、白目と虹彩の割合、虹彩の鼻側への寄り |
| 鼻・口 | 目との高さ関係、鼻先から口までの距離、顔の内側か輪郭上か |
| 髪・帽子 | 頭頂の高さ、後頭部のふくらみ、耳前の髪、襟足、毛先が顔にかかる範囲 |
| 首・胴・腕 | 顎の奥から首が出る位置、襟の開き、肩と袖の重なり、頭と胴の前後関係 |

数値は方向ごとの元画像から決めます。主人公で使った目の縮小率やミナの肩位置を、別キャラクターの共通正解として流用しないでください。

## 2. 目は単純な卵型にしない

主人公では「顔に対して目が大きい」「青い部分の位置と白目の割合が違う」「輪郭が単純な卵型」という指摘がありました。

- 上まぶたの弧、目頭と目尻の角、浅い下辺を分けて設計する。
- 白目・虹彩・瞳孔・反射光を別部品にする。虹彩を鼻側へ寄せたとき、外側の白目がどう見えるか確認する。
- 虹彩はまぶたの内側でクリップする。下側に不自然な白い縁を残さない。
- 正面、斜め前の手前側／奥側、横向きで輪郭と見える幅を描き分ける。
- 大きさを直すときは、白目と虹彩の比率を保った全体縮小と、虹彩だけの位置・大きさ調整を区別する。

主人公では試作04で目全体を92%にしました。これはその時点の主人公への修正値です。共通部品は `prototypes/shared/face-parts.mjs`、キャラクター別の指定は各 `character.mjs` に置きます。

## 3. 顔・鼻・頬の輪郭

主人公の斜め前では頬がギザギザになり、ミナでは下ぶくれに見える問題がありました。

- 頬から小さな顎へ連続した曲線でつなぎ、途中に意図しない折れや突起を作らない。
- 斜め前の鼻は、元画像が顔の内側に描いているなら輪郭を突出させない。横顔の鼻先とは別に扱う。
- 鼻の高さ・向き、口との距離を元画像から合わせる。鼻だけを整えても口が離れていれば印象は変わる。
- 下ぶくれは顎だけを狭めて終わらせず、頬の最大幅の位置と、下半分が膨らむ量を確認する。
- 頬のギザギザは顔パスだけでなく、後ろ髪が顔の外周へ交互にはみ出していないか調べる。

輪郭、鼻、髪の重なりを別々に確認してから合成します。右斜め前・左斜め前の両方を実際に表示します。

### 横顔が大きく見える場合

3人の左右向きでは、鼻先から耳までの幅と頬の面積が大きく見えました。顔全体と頭全体を区別し、まず顔・目・鼻・口・耳を同じ変換で縮め、その後に髪・帽子を含む頭の輪郭を少し調整しています。顎の高さと耳側を基準にし、首や襟を一緒に縮めないことが接続を保つポイントです。

現在の左右向きの作画では、顔の横幅／高さは修正前に対して主人公が約85%／90%、ミナが約86%／91%、ピノが約81%／88%です（顔の縮小と頭全体の縮小を掛け合わせた値）。これらは各 `character.mjs` の横向きだけに適用し、右向きは反転で揃えています。方向別の頭の高さ設定とは別の、作画原本側の調整です。

顔を縮めた後は、元の位置に残った前髪が目を隠さないか、耳前の髪と耳が離れないか、顎と襟に隙間が開かないかを確認します。公式の各キャラクターテストで出力する `prototypes/<character>/profile-comparison.png` は元画像と生成画像を同じ拡大率で並べています。個別の頭の外接枠へそれぞれ拡大すると大きさの違いを隠してしまうため、比較時は同じ倍率を使います。

### 斜め前は横向きと別に比較する

左右向きの修正値を斜め前へそのまま適用しません。元画像との同倍率比較では、主人公は頬・顎の面積、ミナは主に顔幅、ピノは幅と高さの両方を調整する必要がありました。主人公の顔は幅90%・高さ88%、ミナは94%・98%、ピノは91%・92%へ縮小しています。ピノは頭全体にも幅98%・高さ99%の小さな調整を重ねています。いずれも今回の修正前に対する値です。

目・眉・鼻・口・耳と輪郭をまとめて調整し、顎付近を基準に襟への接続を保ちます。髪の位置は顔と別に確認し、頬の端から毛先が交互に出る問題や、前髪で目が隠れる問題を再発させないようにします。左右の斜め前は反転で揃え、既に調整した真横と残る方向は維持します。公式テストは `prototypes/<character>/front-quarter-comparison.png` に斜め前の同倍率比較も保存します。

## 4. 髪は頭皮から連続させる

「目や顔から生えている」「貼り付けた毛束に見える」「後ろ髪が顎ひげに見える」「横向きで耳の前の髪がない」という指摘を再発させないことが重要です。

- 頭頂 → 前髪 → こめかみ → 耳前の髪を、根元のつながった輪郭として設計する。
- 毛量を増やすときも、顔面の途中を起点に尖った毛束を置かない。
- 細い筋や光沢は髪の輪郭内へクリップする。毛束ごとの濃い輪郭線を増やしすぎない。
- 白髪など明るい色では、前髪・後頭部・こめかみの別々の塗りと輪郭が帽子の縁に見えることがある。髪全体の輪郭と陰影を連続させ、内部の毛束は閉じた境界線で分割せず、細い毛流れで表す。
- 正面から見える後ろ髪には首元の開きを作る。顎の下を茶色い帯でつながない。
- 横向きは耳前の髪と耳、後頭部の髪を分けて観察する。左右どちらにも同じ欠落がないか確認する。
- 背面は髪が襟を覆う場合がある。正面と同じ描画順を機械的に使わない。

2Dの描画順と、頭・胴を別メッシュにした3Dの重なりは別問題です。合成シートで自然でもリグ表示で崩れることがあります。

## 5. 帽子・スカーフ・襟

### 帽子

主人公の左右向きでは帽子が平たく見えていました。頭頂だけでなく後頭部を包むふくらみと、下へ回り込む裾を作ります。ベルト、バックル、縫い目もその曲面に沿わせます。横向きを修正したら斜め前との厚みのつながりを確認します。

### スカーフ

背面・左右斜め後ろも正面と同じ密度で確認します。首周り、結び目へ集まるひだ、結び目、左右の垂れ布、折り返しと影を分けて描きます。斜め向きは奥側のひだを狭めます。単に赤い塊を置いて終わりにしません。

### 首と襟

首は顎の奥から胴へ接続させます。ミナでは正面用の縦長の首を斜め前・横に共用したことが不自然さにつながりました。斜め前は奥側の小さな襟と手前の広い襟、横は襟足へ上がる襟など、向きに応じて形を設計します。

## 6. 襟の二重表示から得た切り出しルール

ミナでは、首の絵や位置を調整しても襟が二重に見えました。原因は合成画像の同じ襟を頭と胴の両方に読み込んでいたことです。

従来のリグはセル128pxに対して、頭の縦UVが `0.4〜0.955`、胴が `0.05〜0.45` です。UVは下端基準なので、画像上端から頭は約5.8〜76.8px、胴は約70.4〜121.6pxを使います。約6.4pxの重複帯があり、襟が入ると2回描かれます。頭と胴の拡大率・位置・奥行きが異なるため、同じ画素でも一つに重なりません。

新規キャラクターは次の分離を基本にします。

| レイヤー | 含めるもの | 含めないもの |
|---|---|---|
| 頭 | 顔・耳・髪・頭に付く装飾 | 首・襟・服 |
| 胴 | 首・襟・上着・ベルト | 顔・髪 |
| 比較用合成 | 観察用の全体像 | リグ用2枚の代わりにはしない |

- スカーフなど境界をまたぐ装飾にも担当レイヤーを一つ決め、両方へ描かない。
- ミナは `headSheetUrl` / `bodySheetUrl` を分け、胴の `bodyTopV = .54` で首まで読み込む。胴の箱を上へ延長し、服の縮尺と裾の位置を維持している。
- UV範囲だけ変えて同じ箱へ貼ると、絵が引き伸ばされる。範囲・ジオメトリの高さ・基準位置を一緒に確認する。
- 位置の微調整で二重描画を重ね合わせて隠さない。最初に各メッシュの元画像と切り出し範囲を調べる。
- 歩行時は頭と胴の上下動が異なるため、待機だけでなく動作中も確認する。

## 7. 腕・肩・頭と胴の3D配置

ミナでは袖が胴から離れて見え、顔より胴が前に出て見える問題もありました。

- 腕の回転支点を肩に置き、袖上端が胴体へ少し入り込む配置にする。手の位置だけを合わせても肩はつながらない。
- 肩幅、腕の開き、肩の高さ、袖の中心位置を別々に確認する。
- ゴンタでは袖と胴の交差テストが通っていても、袖上端が首元まで上がって見えた。接続があることと、見た目の肩位置が正しいことは別に判定する。通常サイズの正面・斜め前で襟・顎と袖上端を比較し、支点の高さと袖の支点内位置を調整する。
- 横・斜め前で顎、首、肩の順序を見る。頭の向きに対する前進量と、カメラに対する奥行きを混同しない。
- 袖と胴の交差、肩の胴への追従、道具の手元への追従を動作の複数位相で確認する。
- キャラクター固有の値は `rig-profile.mjs` とマニフェストに記録する。共通リグの既定値を変えて他のキャラクターまで動かさない。

元画像自体に不自然な腕の接続がある場合は、その不自然さをコピーするより、胴体と一体に見える接続を優先します。これはユーザーから明示された方針です。

### 方向別の頭と胴の間隔

3人とも、特に斜め前で顎や髪が襟・肩へ食い込んで見えました。レイヤーと切り出しを確認した上で、`rig-profile.mjs` の `headLiftByDirection` に上方向の追加量を保存します。これはUV中心のずれを隠す補正ではなく、頭メッシュと胴の配置間隔です。全方向共通の `headOffsetY` に加算し、待機・歩行・攻撃の上下動にも引き継ぎます。

今回の追加量（リグの座標単位。頭の高さは0.5）:

| キャラクター | 正面 | 左右斜め前 | 左右 | 左右斜め後ろ | 背面 |
|---|---:|---:|---:|---:|---:|
| 主人公 | 0.015 | 0.025 | 0.020 | 0.020 | 0.018 |
| ミナ | 0.025 | 0.040 | 0.028 | 0.035 | 0.030 |
| ピノ | 0.025 | 0.040 | 0.025 | 0.032 | 0.028 |
| イナホ（新規制作時の設定） | 0.018 | 0.028 | 0.020 | 0.024 | 0.022 |
| ゴンタ（新規制作時の設定） | 0.018 | 0.030 | 0.022 | 0.022 | 0.018 |
| ジンベエ（新規制作時の設定） | 0.020 | 0.028 | 0.022 | 0.022 | 0.018 |
| ワタリ（新規制作時の設定） | 0.018 | 0.026 | 0.022 | 0.022 | 0.018 |

斜め前は顎と襟、横は首と肩、背面は襟足と服のつながりを修正前後で確認しました。主人公はスカーフを含む合成シートなので、分離シートの2人より小さくしています。この値を新キャラクターへ一律にコピーしないでください。離しすぎて首に透明な隙間が開く場合は、位置だけでなく首の作画・担当レイヤーを再確認します。

ゲーム側で `node tests/authoring/head-spacing.test.mjs` を実行すると7人×8方向の比較画像 `prototypes/<character>/head-spacing.png` を出力します。待機・歩行・攻撃の複数位相で補正が維持され、方向変更で累積せず、胴・腕・道具と左側の元画像が変化しないことも検査します。比較画面右側だけに設定を渡し、未指定の本編キャラクターは従来の配置を保ちます。

### 装備の重なりと振る動作を分けて扱う

以前、顔へのめり込みを避ける調整でハンマー・剣を振る動作が不自然になり、ユーザーの指示で戻しました。装備が顔の前を横切ること自体は、振る軌道によっては自然です。静止画で顔が隠れないことだけを優先しないでください。

- 柄を握る点、肩・肘の接続、振りかぶりから振り下ろしまでの軌道を確認する。修正後も道具が手に追従することを確かめる。
- 剣は刃が進行方向を向いて切るようにする。平たい面でたたく向きになっていれば、まず柄から剣先へ伸びる軸の周りの回転を見直す。
- 現在の剣の補正は、その軸の周りだけを回して刃の向きを合わせ、握り位置・腕の動き・剣先の軌道を維持している。ハンマー等へ同じ補正を適用しない。
- 正面・背面を含む8方向と、待機・歩行・攻撃の複数位相で確認する。姿勢全体の変更が必要な場合は、別の変更として意図と動作を検証する。

ゲーム側の `node tests/authoring/sword-edge.test.mjs` が刃の向き、握り位置、腕・剣先の軌道、剣以外の向きの維持を検査します。顔や頭の作画調整とは独立した検査です。

## 8. 8方向シート・正規化・左右反転

- 標準出力は512×256px、4列×2行、1セル128×128px、透明背景。
- 方向順は `front, front_left, left, back_left, back, back_right, right, front_right`。
- 正面・左斜め前・左・左斜め後・背面を作り、対称なキャラクターの残り3方向を反転する。
- 非対称な髪飾り・服・装備は別処理にする。単純反転で左右の持ち物まで入れ替えない。
- 手足・道具・床の影はシートへ焼き込まない。
- ゲームの `tools/normalize_sheet.mjs` で合成画像を正規化する。中心は `u ≈ .494`、下端は標準セルの約121px。
- 分離した頭・胴にも合成画像から得た同じ移動量を適用する。頭だけを独立に正規化すると髪の下端が胴の裾の基準へ移り、接続が崩れる。
- リグの方向別 `artCenters` で絵の中心ずれを隠さない。元の作画と正規化を直す。

## 9. 修正時の切り分けと確認順

1. 元画像、現在の合成シート、実際のリグ表示を同じ方向で並べる。
2. 合成シートでも崩れるなら、輪郭・部品配置・描画順を調べる。
3. リグだけで崩れるなら、頭／胴の元画像、UV、拡大率、位置、奥行き、上下動を調べる。
4. 頭と胴を個別に見る。襟や髪が誤った側に残っていないか確認する。
5. 一度に関係のない部位まで変更せず、原因に対応した最小限の変更を行う。
6. 指摘方向に加え、反対側・正面・背面も確認する。
7. 拡大比較で形を確認し、通常サイズで印象とつながりを確認する。
8. 待機・歩行・攻撃、道具、水中色、狭い画面で確認する。

自動テストは画像の配置や接続を検査できますが、「元画像に似ている」ことまでは保証しません。テスト合格と目視評価を区別してください。

### 比較条件と変更範囲の確認

元画像と生成画像は、同じ方向・カメラ・照明・表示倍率・アニメーション位相で比べます。頭ごとに外接枠へ合わせて拡大すると大きさの差が消えるため、共通の切り出し寸法を使います。左右の表示位置による遠近感もあるので、一方向の一枚だけで決めず、反対向きと2Dシートも見ます。

修正前に、対象方向、動かす部品、維持する部品を決めます。作画を変えたら原本から再生成し、生成PNGを直接修正しません。対象方向だけを変えた場合、他のセルが画素単位で維持されているかを差分で確認できます。左右向きの修正ではセル2・6、斜め前ではセル1・7が対象です（0始まり）。今回の3体では、それ以外の6方向の画素一致を確認しました。

ただし、輪郭変更に伴って正規化の移動量が変わる場合があります。胴のPNGも変わったときは、原画の胴が変更されたのか、頭と共有する正規化量だけが変わったのかをマニフェストで切り分けます。差分を消すために頭と胴を別々に正規化しないでください。

| 確認画像（ゲーム側 `prototypes/<character>/`） | 用途 |
|---|---|
| `rig-8dir.png` | 全8方向の元画像と生成画像、方向間の一貫性 |
| `profile-comparison.png` | 真横の顔・耳・襟・後頭部を同倍率で比較 |
| `front-quarter-comparison.png` | 左右斜め前の顔幅、頬・顎、目と髪の重なりを同倍率で比較 |
| `back-quarter-comparison.png` | 左右斜め後ろの帽子・髪・耳を含む頭全体と、首への接続を同倍率で比較 |
| `head-spacing.png` | 方向別の頭の高さ補正を無効／有効にした配置比較。任意の過去版との比較ではない |
| `sword-edge-preview.png` | 剣の向きの目視確認。動作全体は対応テストと合わせて確認 |

最初の4種類は各キャラクターの公式テスト、後ろの2種類はそれぞれ専用テストで更新されます。作画更新だけではすべての比較画像が更新されるわけではないため、古い出力を最新の確認結果として扱わないでください。

## 10. 次のキャラクターの開始・完了条件

コード方式で再利用しやすいのは、方向順、目や鼻の部品、パレット、左右反転、レイヤー分離、出力と正規化です。同じコードから再生成でき、衣装色や部品の調整を全方向へ反映できます。一方、顔の比率・髪型・服の量感は個別の観察と作画が必要です。共通部品を使うことと、全員を同じ顔にすることを混同しないでください。

制作を始めるときは、元のNPC ID、参照画像、特徴、左右非対称な要素を記録し、ミナの分離出力を基礎に `prototypes/<character>-8dir/` を作ります。共通の目・鼻・SVG部品・方向順を使い、元の他キャラクターの顔比率をそのままコピーしないでください。

完成判定には以下を揃えます。

- 8方向の作画原本、頭・胴のSVG／原画PNG／正規化PNG、比較画像。
- 方向順・サイズ・正規化量・移植先候補・リグ設定を記録したマニフェスト。
- 元画像との目視比較、境界の二重表示と欠落がないこと、リグでの動作確認。
- 再生成コマンド、必要な依存関係、既知の差異・未確認事項。

既存のゲーム比較ページと公式テストの使い方は、[主人公の手順](../prototypes/adventurer-8dir/README.md)と[ミナの手順](../prototypes/mina-8dir/README.md)を参照してください。画像だけでなくリグ設定と読込方法まで揃えてから、本編へ移植します。

## 11. モンスターの制作（スライム）

人型と違い、スライムは全身を1セルへ描き、A・Bの2枚を `MonsterSprite` が約0.38秒ごとに切り替えます。頭胴分離・3D手足・人型のUV窓は使いません。スライムの初回試作は [専用手順](../prototypes/slime-8dir/README.md) を参照します。

- 元画像の全方向と両ポーズを観察する。スライムでは正面2眼、横1眼、斜め後ろ・背面は顔なし。
- 全体の輪郭・目の位置と割合・口・頬・光沢を個別に設計する。人型の目をそのまま流用しない。
- 光沢の向きと顔の向きを分ける。左右の顔を反転しても、照明による光沢まで機械的に反転しない。
- 伸縮は接地位置を基準にする。A・Bで下端を揃え、切り替え時に左右や上下へ揺れないことを確認する。
- 4列×2行・128pxセル、方向順は人型と共通。公式の正規化で中心と下端を揃え、画素欠落がないことを確認する。
- `MonsterSprite` はセル内の横・縦 `.02〜.98` を切り出す。人型の頭・胴の窓やサイズ基準と混同しない。
- 2枚の絵の変化と、ゲームの移動・ジャンプ・攻撃ロジックは別。比較画面へ未実装の戦闘動作を混ぜない。
- 本編と同じクラス・倍率・切り替え間隔を使い、左右の元画像／生成画像は同じ位相で比較する。
- 全方向・A/B固定・自動切り替え・水中色を検査する。`rig-8dir-a.png` と `rig-8dir-b.png` がゲーム側の比較出力。

スライム用画像はボスにも流用されています。試作中は本編の参照先を変更せず、最終移植時に拡大・着色したボス表示も確認します。

### 眉と目の境界

スライムでは、眉より上に白目・黒目が見える問題がありました。眉を最後に描くだけでは隠しきれないため、目の上端と眉の下端に同じ曲線を使い、虹彩・瞳孔・反射光を目の形へクリップします。正面だけでなく反転側、横、両ポーズで確認します。

### 飛行モンスターと羽ばたき（おおこうもり）

- 体・耳・目と翼を別に作る。羽ばたきを全身の縦横変形だけで作らない。翼の付け根、手首、翼膜の骨、膜の谷をつなぐ。
- 真横は翼が細くなるが、元画像で見える手前の翼まで体の後ろへ隠さない。斜め前・斜め後ろは奥の翼を短く描く。
- 元画像の飛行用余白と本編の `yOffset` を確認する。おおこうもりは `scale=.85`、`yOffset=.4`。地上キャラの接地下端を機械的に適用しない。
- 今回は公式正規化の後、全方向・A/Bに共通の14px上移動を適用し、下端107pxで保存する。画像内の体格を維持し、比較リグは元画像と同じ条件とする。方向ごとのリグ補正では隠さない。
- A/Bは体と足を固定し、翼だけを描き替える。将来の大きな羽ばたきで翼が足より下へ来る場合は、外接枠の下端ではなく体の基準点を固定する方法へ見直す。
- この余白と倍率はおおこうもり固有で、スライム・イカなどの共通正解にはしない。

手順と既知の差異は [おおこうもりのREADME](../prototypes/night-bat-8dir/README.md) を参照。CH1～3の未制作一覧は [制作一覧](../prototypes/README.md) を更新する。

### 耳・手足・しっぽの接続と前後関係（おおねずみ）

- 胴体の縮小後も、部品の付け根を体の内側へ十分に重ねる。おおこうもりの翼と同じく、元画像の部分形状だけでなく合成後の接続を確認する。
- 丸い耳は方向で描画順を変える。横・斜め向きの手前の耳を体の後ろに置くと上半分だけが見え、特徴が失われる。
- しっぽは正面・横では胴体の後ろ、背面側では手前に描く。同じ部品を前後へ二重に描かず、根元を体へ接続する。
- 接地する足はかがみ変形の外へ置き、通常姿勢と変形後で下端を確認する。しっぽの形で外接枠が変わるため、正規化後の左右の揺れも確認する。
- 全16セルの不透明領域を検査し、大きな孤立領域があれば耳・手足・しっぽの浮きを疑う。線のつながりだけでは見た目の自然さを保証しないため、元画像との目視比較も行う。

個別の形状・再生成・既知の差異は [おおねずみのREADME](../prototypes/field-rat-8dir/README.md) に記録する。

### 泥の輪郭・まぶた・接地（どろたぼう）

- 元画像に独立した腕や足がなければ、人型や動物の部品を流用しない。泥の塊と地面に広がる泥だまりを連続させる。
- 草の根元を泥に重ね、体の沈み込みと一緒に変形する。草の先だけが別の位置に残らないようにする。
- まぶたの厚い泥と白目・瞳を分ける。瞳は目の輪郭でクリップし、まぶたの上へ出さない。真横の目は体の内側へ収める。
- 細かな斑点は体の輪郭でクリップし、外周に張り付くしずくは付け根を本体と重ねる。背面にも凹凸を描く。
- 沈み込む姿勢は下端を基準とし、正規化後の2枚で接地位置を比較する。共用画像のボスは最終移植時に拡大・着色でも確認する。

固有の比率・色・表示倍率は [どろたぼうのREADME](../prototypes/dorotabo-8dir/README.md) を参照する。

### 白い胴体と複数の腕（イカ）

- 胴体を全身変形させるだけで腕の動きを作らず、根元を固定して腕の曲線を描き替える。
- 胴体の下端が腕を隠しすぎると細い房のように見える。付け根から先端への太さと、胴体から連続する輪郭を確認する。部品境界の線を横一文字で残さない。
- 奥と手前の触腕を方向ごとに描き分け、腕・吸盤が離れて浮かないことを全16セルで検査する。
- 白い部品は青い陰影で厚みを示す。左右反転時も胴体の光の向きを保つ。
- 浮遊する画像の余白と本編の `yOffset` を別に確認する。イカの一律9px上移動・下端112pxはイカ固有の設定で、他のキャラクターに一律適用しない。
- 比較画面の上下動は元画像と生成画像へ同位相で適用し、固定ポーズは静止させる。本編の高度制御と二重加算しない。

個別設定は [イカのREADME](../prototypes/squid-8dir/README.md) を参照する。
